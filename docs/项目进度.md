## 关键决策（别再重复讨论）

- 框架：**Spring Boot 3.5.16 + MyBatis-Plus 3.5.9 + Thymeleaf**，`java.version=25`；
  已升级至维护中的 Spring Boot 3.5.x 支持 Java 25，保留 Boot 3 主版本
- 数据库：**MySQL 9.7 为主（profile `mysql`，默认）+ H2 内存（profile `h2`）**，靠 profile 切换
- MySQL 驱动锁 **9.1.0**（Boot 默认的 8.3.0 连不上 9.x 服务端），连接串必须带 `allowPublicKeyRetrieval=true&useSSL=false`
- 建表：`db/schema-mysql.sql` 全是 `CREATE TABLE IF NOT EXISTS`，启动时执行，不清数据
- 题库：存 `t_question`，选项用 `options_json`（JSON 数组），不放 option_a~d 四列
- 题库种子：`resources/seed/questions.json`（首批 80 道）+ `questions-extra-*-a/b.json`（扩充 200 道）
  + `QuestionSeeder`（多文件、按「分区+题干」增量补齐，幂等）。
  这样一份数据同时喂 MySQL 和 H2，不用维护两套 INSERT；老库启动时会自动补进新题
- **题库自动补充（让游戏自己补题）**：`QuestionAutoFillService` 调大模型出题 → 校验 → 写 `t_question`。
  按**难度**补缺口而不是按总数（简单 8 / 中等 6 / 困难 6），因为困难档一局抽 10 题且只抽难度 2+3；
  四道闸门：mock 通道默认不入库、结构校验（4 选项/下标/长度）、「分区+题干」去重、单次 `max-per-run` 预算。
  触发点：启动（`on-startup`，默认关）、定时（`cron`，默认 `-` 关闭）、后台按钮 `POST /admin/questions/autofill`
- 游戏模板：**已定 C 知识闯关**。A 打地鼠 / B 记忆翻牌 的页面、脚本、路由
  与 `GameTemplate` VO **已从工程移除**（不是隐藏，是删除；需要时可在
  `2076d9f` 这个提交里找回）。`/games` 保留为入口，302 跳到 `/games/quiz`
- 登录：**Session + 拦截器**，没用 Spring Security 过滤器链，只引
  `spring-security-crypto` 做 BCrypt。理由：不改变现有 URL 行为，
  课程作业体量够用，也更容易讲清楚。拦截见 `AuthInterceptor` / `AdminInterceptor`
- 导航：全站统一 `fragments/nav.html`，改一处等于改全站
- 权限：`/profile` 需登录，`/admin` 需 ADMIN，未登录跳 `/login?redirect=原地址`
- 演示账号：`player01 / password`、`admin / password`（种子数据里的 BCrypt 摘要）
- 项目名：显示名 **魔识**，构建标识 **moshi**（jar 为 `moshi-0.1.0-SNAPSHOT.jar`）。
  `com.example.minigame` 包名与 `minigame` 库名**故意不动** —— 改包名要动 59 个文件的
  import，改库名要做数据迁移，风险远大于收益
- 判分：**服务端判分**。`POST /api/quiz/start` 只下发题干和选项，正确答案留在
  Session 的 Round 里（30 分钟过期、交卷即删）；`POST /api/quiz/submit` 比对、
  算分、写 `t_score`。耗时用服务端计时，不采信前端。
  **旧的 `GET /api/quiz/questions` 已删除**，它会把 answerIndex 一起发下去
- 计分（三档难度 + 四大机制）：难度分档基础分（简单10/中等20/困难30）
  + 连击加成（连续答对第 n 题额外 (n-1)*2，答错清零）
  − 失误扣分（答错/超时 -5）+ 速度加成（提前完成每秒 +2、最多 +50）
- 难度档：简单(5题/20s/难度1)、普通(7题/15s/难度1+2)、困难(10题/10s/难度2+3)，
  题目按难度递进排列；新增 `POST /api/quiz/answer` 逐题即时反馈 + `GET /api/quiz/modes`
- 题库：共 280 道（每分区 56 道：原有 16 + 扩充 40，难度 1/2/3 约 40/36/32 道）；`QuestionSeeder` 按「分区+题干」增量补齐
- 排行榜：分数降序、同分按耗时升序；`ScoreService.top()` 先用 SQL 取前 N，
  再用 `listByIds` 批量补昵称（避免 N+1）
- 未登录也能答题，但 `submit` 时 `saved=false`，不写库（页面上会提示去登录）
- 任务进度**不建进度表**：直接按 `t_score` 里符合条件的局数实时算，
  任务和成绩永远一致；领取记录单独存 `t_user_task`，(user_id, task_id) 唯一防重复领奖
- 素材：文件落磁盘 `uploads/yyyyMM/<uuid>.<ext>`，库里只存相对路径；
  只放行 png/jpg/jpeg/gif/webp，落盘名用 UUID 重生成（防 `../` 路径穿越）；
  静态访问靠 `WebConfig.addResourceHandlers("/uploads/**")`
- 大模型：`LlmService` 一个接口，`RoutingLlmService`（`@Primary`）按当前设置路由到
  `mock`（模板拼题，离线可演示）/ `real`（OpenAI 兼容 `/chat/completions`，默认指向 DeepSeek）。
  **设置可在 `/llm` 页面直接改**（通道 / 厂商 / 模型档位 / 地址 / Key / JSON 模式 / 超时）：
  厂商下拉带出地址与 JSON 支持情况，下面的档位卡片直接挑该厂商的模型
  （如 `qwen-flash` / `qwen-plus` / `qwen-max`、`glm-4-flash` / `glm-4-plus`、`deepseek-chat` / `deepseek-reasoner`），
  卡片上的芯片标了上下文长度和定位（经济 / 均衡 / 旗舰 / 推理）；
  目录里没有的模型名直接在「模型」框手填；厂商目录写在 `static/js/llm-settings.js` 的 `VENDORS` 里，加一档只改这里。
  `LlmSettings` 存内存 + 写 `config/llm-settings.local.json`（已 gitignore），保存即生效、无需重启；
  保存接口仅 ADMIN 可调。
  **real 通道任何失败（无 Key、超时、返回非 JSON）都回落 Mock，且回落结果的 mode 是 `mock`**，
  自动补题据此拒绝入库 —— 网络抖动不会把垃圾题写进正式题库
- 主题：`static/css/theme.css` 用一组 CSS 变量（`--bg` / `--card` / `--line` / `--text` / `--accent` …）
  定义**天蓝浅色**与 `html[data-theme="dark"]` **墨绿深色**两套值，各页面只写 `var(...)`；
  `static/js/theme.js` 在 `<head>` 里同步执行，默认天蓝，点导航栏 🌗 切墨绿并写 `localStorage`（键 `moshi-theme`），
  首屏不会闪。主色填充件（按钮 / 选中导航）用 `--on-accent` 决定字色，墨绿下自动换成深字保证对比度。

## 踩过的坑（别重犯）

1. **PATH 里的 `java` 可能是 Oracle JRE 1.8**，跑 jar 要用 `$env:JAVA_HOME\bin\java.exe`，否则 `UnsupportedClassVersionError`
2. **MySQL 是 9.7 不是 8.x**，驱动和连接参数按上面配
3. **PowerShell 传 `-Dfile.encoding=UTF-8` 会被拆坏**，Maven 参数别带这个；含中文的命令串也容易被吃掉引号，脚本里尽量用纯 ASCII
4. **headless 浏览器截图**在 DSH 沙箱下会因命名管道受限失败，需要提权；且输出路径不能含空格（会被 `--screenshot=` 拆成多个参数）
5. **`~/.m2/settings.xml`** 已配阿里云镜像（原文件有 `.bak` 备份）
6. **中文乱码几乎都是显示层，不是文件坏了**：仓库内 122 个文件已全量校验，全部是合法 UTF-8，
   中文文件名（`docs/项目进度.md`、`docs/环境与选型说明.md`）在磁盘上也正常，`.editorconfig`
   已锁 `charset = utf-8`。看到的乱码只有两种来源，都已处理：
   - `git status` 里文件名成了 `docs/\347\216\257\345\242\203...`：这是 git 的八进制转义，
     已 `git config --local core.quotepath false`，现在直接显示中文
   - 终端里中文成了方块/怪字：控制台代码页是 **936(GBK)**，却在解码 UTF-8 字节。
     已在 `C:\Users\Lenovo\Documents\PowerShell\Microsoft.PowerShell_profile.ps1`（及
     `WindowsPowerShell` 版）里把 `[Console]::OutputEncoding` 设为 UTF-8，
     `.vscode/settings.json` 也指定了默认终端 `PowerShell UTF-8`（`chcp 65001`）。
     **新开一个终端**才生效
   - 以后再怀疑乱码：文件按 UTF-8 严格解码不抛异常、不含 `U+FFFD`、GBK 回环再解码得不到
     正常汉字 → 文件本身没问题，别去「修」它
